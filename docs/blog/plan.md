## 1. 緒言（Introduction）

### 1.1 背景

- 多くの業務システムで **CSV出力** は依然として重要
- 特に以下の要件があると、実装が急激に難しくなる：
    - ユーザ定義のカスタム項目
    - 項目数が動的（0〜N）
    - CSVでは **列として** 出力する必要がある

### 1.2 問題提起

- RDBは行指向であり、**動的列ピボットは本質的に不得意**
- SQLの PIVOT / GROUP BY は「列が静的」であることを前提とする
- アプリ側で処理せざるを得ないケースが現実に存在する

> 本稿では、このような 動的列ピボット問題 を
> 
> 
> Stream / Sequence を用いてどのように扱うかを考察する。
> 

### 1.3 本稿のスコープ

- 対象：**注文データ＋ユーザ定義属性のCSV出力**
- 行展開（Order → Item）は扱わない
- 焦点は **列展開（横持ち化）**
- 実装言語：Kotlin / Java（JVM）

---

## 2. 問題定義（Problem Definition）

### 2.1 データモデル

- 注文（Order）
- 注文属性定義（OrderAttributeDefinition）
- 注文属性値（OrderAttributeValue）

構造：

- 1注文に対し 0〜A 個の属性値
- CSVでは **全注文に対して A 列を必ず出力**

### 2.2 動的列ピボット問題

- 属性が存在しない場合も **空列を出力する必要**
- 列数 A はユーザ操作で変動
- したがって：

> 「属性値が存在する分だけ処理する」では不十分
> 

### 2.3 Stream / Sequence の制約

- Java Stream / Kotlin Sequence は **標準で join 操作を持たない**
- 複数ストリームをキーで結合するには：
    - 事前ロード
    - ネスト化
    - 窓処理
        
        などの工夫が必要

### 3.1 記号定義

ここに数式を書く。

- N：注文数

- V：属性値総数
- aˉ=V/N\bar a = V / Naˉ=V/N：1注文あたり平均属性数

### 3.2 問題の理論的下界

- CSVは列指向フォーマット
- 出力セル数は少なくとも：

- よって **列展開コストはアルゴリズムで消せない**
